# Инструменты и ИИ

Базовый просмотр, HEX, дизассемблирование, редактирование и рецепты работают локально. ИИ необязателен. AnyPatcher не обещает универсальную расшифровку, снятие защиты или запуск любого приложения.

## Локальный помощник

1. Установите Ollama с [официального сайта](https://ollama.com/download/mac).
2. Заранее загрузите выбранную модель с поддержкой вызова инструментов. Модели не входят в DMG и могут занимать много гигабайт. Название не предполагается установленным: приложение спрашивает список у локального сервера.
3. В настройках выберите Ollama, адрес `http://127.0.0.1:11434` и модель. Облачные модели Ollama не используются локальным помощником.
4. Оставьте режим «Только офлайн». Он блокирует облачные API; локальные HTTP-запросы Ollama разрешены.
5. Отключите сеть и проверьте учебный проект от открытия до экспорта. Манифест готовности — список компонентов, не установщик и не архив моделей.

Помощник читает выбранный проект, ищет строки, изучает Unity и машинный код, предлагает проверяемые планы. Он не имеет shell, произвольного доступа к файлам, управления телефоном, применения или экспорта. Изменение вступает в силу только после вашей проверки плана и нажатия «Применить». До 8 итераций и 24 вызовов инструментов за запуск; объём контекста ограничен. Скорость и качество зависят от модели и памяти Mac.

## Облачные API

Поддерживаются Ollama Chat, OpenAI Responses, Anthropic Messages и Gemini generateContent. Для облачных провайдеров требуется собственный API-ключ и доступная модель. OAuth и вход через подписку на чат не реализованы. Подписка на чат сама по себе не является API-ключом.

Ключ хранится в macOS Keychain, отдельно от проекта. В JSON-настройках только адрес, модель и признак наличия ключа. При изменении адреса сервера старый ключ туда автоматически не отправляется. Внешние анализаторы не получают API-ключи из переменных окружения. Настройки не используют ключи Codex или других приложений.

Перед каждым облачным запуском нужно явно разрешить передачу текста запроса и выбранных помощником фрагментов проекта. Весь архив автоматически не загружается. Типовые секреты и персональные пути скрываются, но автоматическая очистка не гарантирует полноту: не отправляйте конфиденциальный проект без разрешения. OpenAI-запросы используют `store: false`; правила хранения самого провайдера проверяйте отдельно. Ключи и тела ошибок API не выводятся в диагностику.

## Декомпиляция

- **Ghidra:** установите релиз с [официальной страницы](https://github.com/NationalSecurityAgency/ghidra/releases) и совместимый JDK согласно требованиям релиза. На macOS в официальном ZIP может не быть готового нативного декомпилятора: сначала выполните сборку по разделу **Building Native Components** файла `GettingStarted.md` из установленного релиза (JDK, Xcode Command Line Tools и Gradle; команда `./gradlew buildNatives` из `support/gradle`). AnyPatcher сам эту установку не запускает и показывает отсутствие нативного компонента. После подготовки выберите `support/analyzeHeadless` в настройках. Встроенный Java-скрипт вызывает настоящий декомпилятор Ghidra в одноразовом проекте. Можно указать файловое смещение функции; иначе показаны первые 40 функций. Тайм-аут анализа — 120 секунд, общий — 240 секунд. Большие бинарные файлы могут не уложиться: используйте отдельную библиотеку.
- **JADX:** [официальные релизы](https://github.com/skylot/jadx/releases). Выберите исполняемый `bin/jadx`. Читает DEX/APK/JAR и показывает восстановленный Java-код. Просмотр ограничен 80 файлами и объёмом текста. Это не восстановление оригинального Android Studio проекта; Java здесь не обещает обратную сборку.
- **Apktool, apksigner, zipalign, keytool:** мастерская APK разбирает Manifest/ресурсы/Smali, хранит отдельную историю правок и выполняет сборку → выравнивание → подпись → проверку. Apktool можно настроить путём к официальному `.jar`. Обычный экспорт архива сам эту цепочку не запускает. Подробности и ограничения — [Сборка и подпись](BUILDS.md).

Программа запускает только известные команды с отдельными аргументами; shell-строки не формируются. Инструменты обрабатывают копии, оригиналы не исполняются. Установка и скачивание внешних инструментов не начинаются автоматически. Внешние приложения не являются изолированной песочницей: используйте актуальные доверенные версии.

Результаты декомпиляции кэшируются по SHA-256 исходного файла, смещению, пути/версии инструмента и версии Java-скрипта. Повторное открытие того же результата не запускает полный анализ заново. Кэш удаляется обычной очисткой кэша проекта.

## Контекст и журналы

Экспорт контекста создаёт новый текстовый JSON с кратким описанием, списком файлов, заметками и выбранными результатами поиска. Полные бинарные файлы не включаются. Проверьте файл перед передачей в другой чат.

Импорт журнала принимает текст до 4 МиБ, скрывает распространённые секреты и сохраняет последние 40 000 символов как заметку. Поиск сообщений о памяти, ресурсах, подписи и исключениях — подсказки с цитатой строки, не доказательство причины сбоя.

## Проверка реализации

Тесты API используют явно подставленные ответы провайдеров: они проверяют форматы сообщений, сохранение function-call/think-signature, ограничения инструментов, запрет облака в офлайн-режиме и отсутствие утечек ключей. Они **не** подтверждают качество выбранной модели или доступность платного аккаунта. Работа внешнего декомпилятора зависит от его фактической установки; отсутствие инструмента отображается как недоступность, без имитации результата.

Официальные схемы: [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling), [Ollama tool calling](https://docs.ollama.com/capabilities/tool-calling), [Anthropic tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works), [Gemini function calling](https://ai.google.dev/gemini-api/docs/function-calling), [Ghidra DecompInterface](https://ghidra.re/ghidra_docs/api/ghidra/app/decompiler/DecompInterface.html).

Проведён отдельный реальный запуск JADX 1.5.6: собственный класс Java 8 помещён в JAR внутри учебного APK, импортирован в проект и декомпилирован через рабочий RPC. Восстановлены арифметическая функция и условная проверка учебного класса. ZIP инструмента проверен по SHA-256, опубликованному GitHub. Этот запуск не проверяет все варианты DEX или коммерческие APK.

Также проверен реальный запуск Ghidra 12.1.4 на macOS arm64: использованы компоненты официального релиза и нативный декомпилятор, собранный из его исходников. Собственный учебный Mach-O импортирован в проект, затем рабочий RPC со смещением 4096 вернул C-псевдокод функции `entry` по адресу `100001000` со статусом `decompiled`. Java-скрипт успешно скомпилирован самим Ghidra. Исследуемое приложение не запускалось; проверка не гарантирует декомпиляцию произвольных защищённых бинарных файлов.
